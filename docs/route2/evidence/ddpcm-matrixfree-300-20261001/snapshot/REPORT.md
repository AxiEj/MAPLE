# 300 中心隐式溶剂低内存实测与后续研究

日期：2026-10-01。位置：`MAPLE-pure-mace-polar-v1`。本报告记录独立研究原型，不是生产能力发布。

## 结论与边界

**已经实际完成 300 个合成连续介质中心的全分辨率精确 ddPCM 算子计算，尚未完成 300 原子完整分子的能量、力、HVP 或解析 Hessian。**

最终候选的 300 档：构造并完成 `Lx`、`L^T y`、`Dx`、`D^T y`，总计 **424.258 秒，进程峰值 RSS 0.918198 GiB**；转置双线性配对最大相对误差 `4.4943e-15`。FP64、`lmax=15`、每球 1202 点、`eta=0.1` 均未降低；没有 FMM、拟合、数值生产导数或容差放宽。

最终核对发现资源估算漏计半径数组的 `8*N` 字节，已用 4 个先失败的回归修正。该修正不改变算子数值，但改变源码哈希。**首次算子阶梯保留为原候选证据；最终候选另有 144 项测试、300 档重放、完整身份账本和真实公开输入负向测试，全部与当前研究源码哈希一致。** 汇总审计见 `accounting-final-audit.json`，不以旧回执替代新候选证明。

完整目标仍是同一 `MACE-POLAR + ddPCM + native legacy-SMD-CDS` 标量的至少 300 原子 E/F/HVP/完整解析 Hessian。当前算子结果不能打开科学准入、化学域、公开 `.inp` 或导数能力。

## 为什么重写为 Torch 后仍可能非常耗内存

语言和张量框架的改写，不会自动改变算法的存储复杂度。这里真正需要改变的是计算表达方式：

- `lmax=15` 对应每中心 256 个系数。300 个中心的系数空间维度为 76800；**单个** FP64 稠密算子理论大小为 `76800^2*8 = 47,185,920,000` 字节，约 43.95 GiB。这是尺寸推算，**不是旧版成功运行的内存测量**；分解、其他算子及导数工作区另计。
- 最终 `900 x 900` Hessian 输出仅 6,480,000 字节。难点不是结果矩阵本身，而是构造、求解及微分过程中的中间对象。
- 原实现的稠密算子、稳定性 SVD、可复用分解及响应中间量，见 `maple/solvation/continuum/ddpcm_response.py`；本次没有删除或绕过这些旧版保护。
- 本次把全局矩阵变为“一个目标球加有界源分块”的动作；D 算子进一步在球谐递推时立即收缩，不生成完整 `源块 x 网格 x 全球谐基` 张量。仅在完整全节点拓扑认证之后，跳过暴露权重**精确等于零**的 D 节点；不是缩减积分网格或近似截断。

推论：本次证据支持“改变存储与收缩方式可以解决这一算子层的内存障碍”，不支持“所有 Torch/MACE/二阶导数内存问题已经解决”。最终 300 档的 D 正向及转置仍各需约 190–192 秒，时间复杂度成为下一项主要约束。

## 实测条件

- CPU，单个科学基准顺序执行，Torch/BLAS 线程数 1。没有本轮 CUDA 基准。
- Python 3.11.14，Torch 2.12.0+cu130，NumPy 2.4.6，SciPy 1.17.1；CPU 模型及所有本次算子值为 FP64。
- 几何：`R_i=(1.63*i, 0.31*sin(1.37*i), 0.23*cos(0.79*i))` Å；中心均标记 C，半径均为 1.7 Å，介电常数 78.39。随机源的种子为 61001，总电荷中和，使用 `l<=1` 源列。
- 这些是用于拆分连续介质复杂度的**合成控制体系**，不是化学合理的 300 原子分子；未调用 MACE 或 CDS。当前 16–500 Da、元素及溶剂限制没有扩展。
- 源分块 8；选定内核 `fused-eager`。**没有 JIT 编译**；`fused-compiled` 只存在未认证的试验入口。
- 每次大运行都有独立 `systemd --user` scope，核实实际 `memory.max=8 GiB`、`memory.swap.max=0`，最长 1200 秒；记录内核峰值及 `max/oom/oom_kill/oom_group_kill` 增量。成功后还须确认所属 scope 不活跃且没有遗留进程。
- RSS、USS 与 cgroup 计费口径不同，不能互换。下表 RSS 使用进程的 `ru_maxrss`；cgroup 峰值另列。采样监视器不是 OS 内存硬上限，真正的硬限制来自 cgroup。

## 实战中保留的失败与修正

1. **转置累加错误**：最初对角赋值覆盖已积累的非对角贡献，9 个测试失败。修复为累加，未改容差；原始红灯日志保留。
2. **径向幂的小优化反而变慢**：50 档从历史约 50.79 秒变成 165.42 秒，已撤回，保留失败结果。
3. **编译并不等于端到端加速**：旧辅助函数的动态导入不能被 Dynamo 跟踪。独立闭合实球谐内核成功编译，微基准约 4 倍提速，但仅编译基函数的 50 档仍需 126.55 秒，其中首个 L 动作约 86.27 秒包含编译。不能把微基准倍率当作 PES 加速倍率。
4. **融合比只编译基函数更有效**：改为球谐值生成后立即收缩；50 档观察到 14.22 秒。与历史非融合约 50.79 秒的比较仅是工程观察，未做相同候选固定热身、多次重复的正式速度认证。
5. **完全埋藏球的转置回归**：即使本球目标行没有活跃节点，其转置输出仍可能已从别的球积累贡献。新增明确的同心埋藏球回归，防止再次覆盖。
6. **监督器必须失败关闭**：修复了 OOM 事件后退出零仍可能被当成成功、名义完成后遗留后代进程、状态查询失败误当作已清理等问题。独立审核及真实 orphan 控制验证通过；旧失败证据保留。
7. **资源估算不是实测**：最终检查发现保留张量公式少计 `N*8` 字节半径；4 个新回归先失败再修复，公式从 `6*N` 改为 `7*N`。实际 300 档漏计 2400 字节，不影响此前实测 RSS 或 OS 硬限，但修正后重新绑定源码并重放，不能继续拿旧哈希当新候选证据。

## 文献与实测如何对应

- **区域分解和 FMM 的方向有原始文献依据。** ddX 2024 论文区分了直接 ddPCM 的二次复杂度和采用 FMM 的线性复杂度实现，并介绍能量及解析梯度。它支持下一步研究误差受控 FMM 的方向，**不等于当前 Torch 标量已经拥有 300 原子解析 Hessian**。[ddX 2024](https://doi.org/10.1002/wcms.1726)
- **FMM 不是本轮成功的原因。** 本轮是相同离散化的直接精确动作；ddPCM 的 FMM 能量/力文献为下一阶段参照。切换时需验证近场/远场、展开阶数及所有导数收敛，不能以“精度一般够用”替代现有门槛。[ddPCM FMM 2022，官方文献表](https://ddsolvation.github.io/ddX/label_references.html)
- **Checkpointing 是补充，不是稠密算子的替代。** PyTorch 官方说明其以反向重算换取少保存激活，非重入变体支持更多 autograd 用法。后续可以针对 MACE 激活试验，但必须先核对本机 2.12.0 行为及二阶导数；本轮没有借此宣称节省。[PyTorch checkpoint 文档](https://docs.pytorch.org/docs/stable/checkpoint)
- **下一步的导数应作用于隐式方程，而非求解器历史。** ddX 官方理论给出非对称块线性系统以及转置伴随系统，并通过双向量收缩计算一阶导数。由 `K(R)x(R)=b(R)` 直接求方向导数，得到 `K*x_v=b_v-K_v*x`；二阶 HVP 还需对伴随方程求方向导数并计入显式二阶项。这一二阶延伸是本项目待实现、待验证的工作，不能因上游一阶公式存在就视为已支持。官方网页当前标注 ddX 0.9.0，本地参照仍为 0.8，没有静默升级。[ddX 官方理论](https://ddsolvation.github.io/ddX/md_docs_theory.html)
- **文献覆盖有边界。** 本轮核查的 ddPCM 力及 FMM 文献支持一阶解析力；未找到足以证明当前标量所需的完整 ddPCM-FMM 核 Hessian/HVP 已可直接复用的上游证据。这里的“未找到”不是证明文献不存在。FMM 的二阶近远场及树拓扑一致性，MACE 源曲率，以及条件数对误差的放大均须独立验证。[ddPCM 力 2017](https://doi.org/10.1063/1.5008329)、[ddPCM FMM 2022](https://doi.org/10.1063/5.0104536)
- **Gaussian 不能仅凭原子数给出可信内存定值。** 本轮没有 Gaussian 的同体系、同基组、同任务实测；`%Mem` 是用户配置项，不是某个 300 原子任务已测得的 RSS。官方 GPU 示例的服务器配置也不能当作每个任务的内存需求。因此本报告不编造“Gaussian 300 原子一定需要 X GB”，也不拿四次连续介质动作与整套 DFT/Freq 比快慢。[GaussView 官方手册的 Link 0 Memory Limit](https://gaussian.com/wp-content/uploads/dl/gv6.pdf)

## 下一步优先级

1. **小体系精确求解及稳定性研究**：完整正向/伴随状态和原系统真残差；明确预条件位置及转置预条件。现有小型 GMRES 只是诊断，不能以收敛或随机条件估计替代原全 SVD 的保护语义。
2. **解析方向导数**：实现流式算子、RHS、psi 的 JVP/VJP，再做方向化二阶收缩。通过隐式方程求导，不保存整个 Krylov 迭代反向图。先对小体系逐项比较，保持 E `1e-10 eV`、F `1e-8 eV/Å`、H/HVP `1e-6 eV/Å²`、每次原系统残差 `1e-12` 门槛。
3. **完整标量连接**：不能遗漏 MACE 源对坐标的响应与二阶曲率，也不能用固定源原生力冒充完整模型力；CDS/DAREAL 身份同样要保留。
4. **再解决直接动作的时间成本**：精确小体系 E/F/HVP/H oracle 建立后，研究误差受控 FMM；不必先强行跑完极慢的直接 300 原子完整 Hessian。Checkpointing、GPU、缓存和方向分块在其后按实测收益选择。
5. **最后才讨论支持范围**：合成 300 中心算子、300 中心求解、300 原子全 PES、化学适用域、普通 `.inp` 使用，是五个不同验收层。当前只达到了第一个的实测里程碑。

本轮没有解决确定性稳定性证书，没有 300 档求解或导数结果；未测紧凑 300 中心几何，也未做正式多次重复性能统计。这些缺口保持显式，不通过扩大能力标志掩盖。
