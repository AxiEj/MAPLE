2. 新架构：算法层只消费 contract，不识别模型身份

核心设计是把“怎么批量跑模型”从 OPT/TS/NEB/PRFO 算法里抽出去，收敛到 calculator contract。

Input

MAPLE task

#freq、#opt、#ts(method=neb) 等仍按原任务入口解析。

Knob

batch_size

统一内存/速度 chunk cap；支持正整数或 auto；PBC 下拒绝 batch。

Contract

calculate_many

返回 BatchResult，不依赖 calc.results 副作用。

Evaluators

FD / Path / HVP

Hessian、NEB path、Dimer HVP fallback 共享同一批量取数层。

Backend

model-specific batch

ANI tensor batch；AIMNet2 mol_idx；MACE graph batch；UMA AtomicData；不安全后端 fallback。

3. 前后对照：从分散循环到统一 evaluator

下面不是伪代码式美化，而是对代码结构的最小抽象：旧代码每个模型/算法自己循环；新代码先生成结构批，再通过 contract 取回结果。

原来：每个模型手写 +δ/-δ 循环

例：ANI/AIMNet2/MACE/UMA 都有各自的 finite-difference Hessian 循环。

for atom in movable:
  for axis in xyz:
    pos_p = pos0 + delta
    Fp = model.calculate(pos_p)
    pos_m = pos0 - delta
    Fm = model.calculate(pos_m)
    H[row, :] = -(Fp - Fm) / (2*delta)

现在：统一构造位移批，后端自行 batch/fallback

算法定义仍是中心差分；只改变 force evaluations 的调度方式。

forces = chunked_calculate_many(displaced)

4. 科学边界：哪些变了，哪些没有变

这里把“性能工程”和“物理/优化算法”分层，避免把速度改动误解成科学定义改变。

没有改变

  • FD Hessian 仍是中心差分 -(F+ - F-) / 2δ。
  • NEB/CINEB tangent、spring force、climbing image 公式不变。
  • PRFO step、trust radius、mass-weighted coordinate 逻辑不变。
  • 默认 PRFO 仍每步 exact Hessian。

改变的是调度

  • 多个 geometry 的 E/F 通过 calculate_many() 一次提交。
  • analytic Hessian 可按 row chunk 做 exact VJP。
  • NEB path snapshot 可一次取全体 images 的 E/F。
  • accepted trial 的 E/F 被 carry forward，少一次重复 forward。

新增安全门

  • PBC + batch_size 拒绝；PBC evaluator 走顺序 fallback。
  • TS 参数 typo 进入 unknown-param gate。
  • PRFO 收敛后必须 one-imaginary-mode validation。
  • Hessian reuse 失败或 reject 后强制 exact refresh。

6. 风险门控图：哪里允许加速，哪里必须保守

允许：非 PBC E/F path batch

Risk: low-medium · guarded by result parity tests

NEB/CINEB path 一次拿多 image E/F，但 tangent/spring/optimizer 不变。

谨慎：analytic Hessian row chunk

Risk: medium · exact math, memory/speed only

仍是 exact autograd Hessian；chunk size 只限制 VJP rows，不切换到 FD。

禁止：PBC batch acceleration

Risk: high · currently fail-closed

没有后端级 PBC batch parity 前，显式 batch_size + PBC 报错，evaluator 顺序 fallback。

Opt-in：PRFO hessian_recalc

Risk: medium · default remains exact

Bofill reuse 适合 close handoff；direct loose PRFO 仍建议默认 exact-every-step。

必须：TS mode validation

Risk reducer · scientific acceptance gate

PRFO 只有力/位移收敛不够，最终要恰好一个非平凡虚频。

禁止：伪造不支持的 true batch

Risk: high · MACEPol example

MACEPol traced checkpoint 多图 batch 不稳定；保留 contract，但不宣称 true batch。

新增：FD Hessian anti-symmetry gate

Risk detector · warn by default, raise optional

中心差分 Hessian 仍会 symmetrize，但先检查 max|H-Hᵀ|/scale，防止真实后端错误被平均掩盖。
